# Test guide

[简体中文](README.zh-CN.md)

This guide describes eight exact targets for unpublished candidate `0.3.2`, default DSH `0.2.2-alpha.2`. Final same-archive reports are separate; specialized or historical runs do not certify the final archive.

Run tests from a Linux source checkout with Node.js 24+, pnpm 12.5.1, and Playwright Chromium:

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm check
```

`pnpm check` runs static checks and all four test groups. Run a group directly while developing:

| Group       | Command                 | Contract covered                                                                                                                                                                    |
| ----------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unit        | `pnpm test:unit`        | Password/TOTP/backup codes, sessions, origin policy, translations, JSON durability and lock recovery.                                                                               |
| Integration | `pnpm test:integration` | Real HTTP and WebSocket sockets, Host/Origin policy, native readiness, cookies, API mutations and revocation.                                                                       |
| CLI         | `pnpm test:cli`         | Real local archive, DSH profile execution, pseudo-terminal prompts, fixed English, invalid --lang/environment checks, JSON output, Unix socket, offline lock and uncertain results. |
| Browser     | `pnpm test:browser`     | Pinned DSH boot, anonymous gate, login, Security & sign-in settings, native settings, workspace, chat stream, upload/preview, SSE/WebSocket and HTTPS forwarding.                   |

The scripts prepare DSH `0.2.2-alpha.2` under `.cache/test-runtime/<version>` and create temporary `DSH_HOME` directories. `DSH_TEST_BIN` can override the executable only when `--version` reports the selected `DSH_TEST_VERSION` (default `0.2.2-alpha.2`); `DSH_TEST_BROWSER` can override the Playwright browser executable. The default is Playwright-managed Chromium.

Positive targets are `0.2.1-alpha.3`, `0.2.1-alpha.4`, `0.2.1-alpha.5`, `0.2.1-rc.1`, `0.2.1-rc.2`, `0.2.1-rc.3`, `0.2.1-rc.4`, `0.2.2-alpha.2`, selected through `DSH_TEST_VERSION`, with CLI/smoke on all eight. Startup uses the real Loader and checks model runtime context, `DSH_WEB_URL` and all Web sections for duplicate URLs/tokens. Native transport covers IPv4/IPv6 HTTP/HTTPS, Host/Origin, uploads/long connections/Secure/CLI revocation on all eight. Missing IPv6/TLS support fails instead of skipping.

The Node HTTP/HTTPS forwarder in `tests/helpers/` stands in for transport without depending on a local proxy installation. `tests/fixtures/tls/` contains a dedicated self-signed test certificate and key for the `.test` hostname. They are never installation or production credentials and are excluded from the archive. Browser chat uses a local model stub. No real external account, OAuth token or paid model request is needed.

The [TLS fixture guide](fixtures/tls/README.md) documents the native listener certificate's IPv4/IPv6 SANs, Node trust and browser public-key pin. The forwarder also validates TLS upstreams, so both HTTPS-to-HTTP and HTTP-to-native-HTTPS chains have coverage.

Do not point these commands at an existing account directory. Browser and CLI fixtures use separate temporary homes; `pnpm smoke` uses the marked `.dev/dsh-home`. The [development guide](../docs/development.md) describes the isolated development lifecycle, and the [deployment guide](../docs/deployment.md) describes a live profile and backup procedure.

Shared `isolatedDshEnv` allowlists Host environment variables, removing real model credentials/endpoints; browser launch also strips ambient HTTP(S)/ALL_PROXY. Before the first key entry, `localModelEndpoint` points native llm-deepseek baseURL at a local HTTP fixture. No key is preseeded and onboarding stays active: native key selection, save, reopen and refresh persistence remain checked. UI-only cases require zero model calls; proxy chat allows only the expected local chat and native session-title POSTs, with counts checked at fixture close.

Official-account coverage in `integration/account-login.test.ts` uses the actual installed DSH `0.2.2-alpha.2` provider from locked development dependencies and a local Platform stand-in to validate PKCE, redirect URI equality, state, callback parsing, session ownership, one-time submission, cancellation, expiry and retries. `browser/account-login.spec.ts` exercises instruction-first authorization, failed loopback navigation and pasted callback completion, blocked popups and eight-language responsive themes. All eight positive targets keep the full account flow; no real official account is used.

`browser/live-config.spec.ts` observes the real Loader and loaded package identities per release, writes true→false→true→false and verifies long connections and restart persistence. Full account-browser branches cover `0.2.1-alpha.3`, `0.2.1-alpha.4`, `0.2.1-alpha.5`, `0.2.1-rc.1`, `0.2.1-rc.2`, `0.2.1-rc.3`, `0.2.1-rc.4`, `0.2.2-alpha.2`, including native Settings save success/failure, immediate new-entry switching and completion of admitted attempts. Login/settings regression covers the five trusted overview values, password/TOTP/current/all-session dialogs, keyboard/focus, cancellation/errors, failed backup-code copying and one-time display. Screenshots mask passwords and backup codes. Full version matrices must reuse one final archive and check SHA-256 after each release, avoiding standard commands that repack inside the loop.

`browser/account-login.spec.ts` triggers real configuration HMR through an ordinary `sessionHours` change on all declared releases and verifies that Settings writes still wait for the native transaction queue and reject genuine nesting. The test-only `fixtures/hmr-config-probe.mjs` uses the real HMR service. The exact `0.2.1-alpha.3`, `0.2.1-alpha.4`, `0.2.1-alpha.5`, `0.2.1-rc.1`, `0.2.1-rc.2`, `0.2.1-rc.3`, `0.2.1-rc.4`, `0.2.2-alpha.2` targets also replace the isolated installed plugin entry and re-enable manual sign-in afterward.

The HMR queue case checks the precise startup maintenance message before and after configuration reload. A separate legacy case copies the same candidate's package manifest and dist into an isolated profile directory, disables the original host row, inserts the copied entry through the public Loader contract and opts into native source watching with explicit HMR `base/root`. It observes real module replacement and the next listener generation, then checks that the same process emitted the warning once and the session still works. Default legacy module watching excludes node_modules; this fixture does not claim automatic replacement there. Normal targets must not emit a maintenance warning. `unit/dsh-support.test.ts` verifies dates, unchanged classification after the deadlines, fictional retirement inputs and process-wide deduplication; these fixtures do not change a real host's version.

`browser/startup-compatibility.spec.ts` checks two damaged-copy paths on all eight: `0.2.1-alpha.3` changes the Host peer because its Loader does not read engines, while the other seven change engines. Loader must skip without importing; every host also gets an injected plugin range and must refuse after import. The profile independently disables webserver. Processes must exit naturally nonzero, all probes refuse, and patch/upstream/candidate archive remain unchanged.

`browser/host-release.spec.ts` fixes seven real round trips: `0.2.1-alpha.4` ↔ `0.2.1-alpha.3`, `0.2.1-alpha.5` ↔ `0.2.1-alpha.4`, `0.2.1-rc.1` ↔ `0.2.1-alpha.5`, `0.2.1-rc.2` ↔ `0.2.1-rc.1`, `0.2.1-rc.3` ↔ `0.2.1-rc.2`, `0.2.1-rc.4` ↔ `0.2.1-rc.3`, and `0.2.2-alpha.2` ↔ `0.2.1-rc.4`. Each keeps the page in one temporary profile/port, checks the native release prompt, reloads to verify authentication, the original session and persisted settings, then restores the starting release. Only `0.2.1-alpha.3` lacks release metadata and reads unknown; every other destination must show its actual full version. No upstream source, version or dependency-graph metadata is changed.

`browser/web-search-settings.spec.ts` registers on `0.2.1-rc.2`, `0.2.1-rc.3`, `0.2.1-rc.4` and `0.2.2-alpha.2`. It opens the native Search/Fetch settings on an authenticated remote Host, verifies `web`, `web-search-deepseek` and `web-deepseek-api`, switches providers, saves endpoints/limits and a test credential, observes validation and an injected transport refusal, then verifies refresh and real process-restart persistence. Anonymous requests and the original cookie after session revocation must fail for settings and credential reads/writes. A local provider counts requests and must receive none; this verifies the settings/authentication boundary without Search/Fetch results, paid requests, or real account authorization. No host provider is replaced.

Fixed-archive verification uses `pnpm verify:packed --archive <archive> --sha256 <recorded-sha256> --dsh-version <exact-version> --suite <suite>` without rebuilding or repacking. The [development guide](../docs/development.md#consume-a-fixed-archive) lists all fixed suites and filter rules. The consumer restores the archive dist before CLI/installation checks, rejects empty or skipped runs, records SHA-256 and counts, and isolates smoke from `.dev` and port 13090. `unit/verify-packed.test.ts` covers damaged/escaping/link archives, actual Node zero-selection output and marked-root protection. Full release validation still requires every declared target's CLI, complete browser and smoke against the same archive.

CI uses the [ordinary/full plan](../docs/development.md#ordinary-and-full-ci-plans). Ordinary keeps eight-version CLI/smoke, complete browser on `0.2.1-alpha.3`, `0.2.1-rc.2`, `0.2.1-rc.3`, `0.2.1-rc.4`, `0.2.2-alpha.2`, host-release on both other Alphas, and rc-bootstrap on `0.2.1-rc.1`. Source/infrastructure/unknown changes, manual/weekly runs and releases run all eight complete browser targets plus independent real refusal on retired `0.2.1-alpha.2`. Ordinary accepts only that negative job’s planned skip; full requires success, and missing/unknown plans or other skips fail. Required files must register real cases; zero-registration exceptions are explicit: LiveShare is inapplicable only on `0.2.1-alpha.3`, `0.2.1-alpha.4`, `0.2.1-alpha.5`, `0.2.1-rc.1`, `0.2.1-rc.2`, `0.2.1-rc.3`, `0.2.1-rc.4`; new-host resource, mux, Search/Fetch and navigation must register real cases.

`browser/rc-navigation.spec.ts` checks global/session/right-sidebar More, native settings/model selection and post-revocation denial on `0.2.1-rc.3`, `0.2.1-rc.4` and `0.2.2-alpha.2`. Market/Creator entries are inspected without installation. Test-only `fixtures/rc-navigation-state.mjs` adds an empty completed turn to a real native session using public sessions/sessionProjections, refuses existing turns, sends no chat and never replaces snapshots; model calls must stay zero. Official dynamic `/models` internals and complete official authorization are unverified.

Independent `scripts/verify-retired.mjs` accepts six explicit retired targets without widening positive selection. It verifies the same digest, published `0.2.0` baseline, real installation rollback and native peer skip/no delayed listener for a whole incompatible bundle. The six-host one-time run belongs to the `0.3.1` migration; current full/releases run only `0.2.1-alpha.2`, ordinary none. See development for commands and report boundaries.

On exact DSH `0.2.2-alpha.2`, `native-transport.spec.ts` compares genuine native asset/fallback bytes and ETags for GET/HEAD/304, rejects anonymous/revoked correct-tag requests, and retains immutable 200 semantics for real bundle/map/chunk artifacts and nonimmutable index behavior. Four real `/api/remote.mux` cases cover native HTTPS/proxy, default/none compression, whole-frame threshold/RSV1, successful ready frames and actual expiry/revocation. The installed native Gateway/ws owns transport and compression.

The new-host `account-login.spec.ts` source-HMR fault case preserves the initial instance on import failure, then throws after genuine replacement initialization to prove old/failed resource cleanup and native automatic rollback. It checks real provider fibers, listeners, state-lock nonces, mux closure, persisted authentication, the first restored Settings save and final lock reacquisition. The copied entry uses one canonical file URL and explicit native watch roots; public log export observes warnings without replacing HMR.

Browser language tests cover all eight plugin dictionaries, login fallback/memory, native accepted preference vs optimistic edits, delayed/unavailable/failed reads and saves, storage failures and sign-out/revocation persistence. DSH's native language catalog is unchanged. CLI tests require fixed English across environment languages and reject every `--lang` form before profile access; the published `0.2.0` retired fixture keeps its historical Chinese contract.

`liveshare.spec.ts` registers only on exact `0.2.2-alpha.2`: real native Host/Owner PKCE/share worker/viewer carriers and stop operations use a local Relay identity/transport stand-in. Viewer clients remain inert for administrator features. Tests do not establish real Relay/OAuth, visitor models or file writes. Partial filtered reports and file placeholders never certify the final eight-host archive.
