# Test guide

[简体中文](README.zh-CN.md)

Candidate `0.3.6` declares eight exact targets: `0.2.1-rc.1`, `0.2.1-rc.2`, `0.2.1-rc.3`, `0.2.1-rc.4`, `0.2.1-rc.5`, `0.2.2-alpha.3`, `0.2.2-rc.1`, `0.2.2-rc.2`. Default/recommended host `0.2.2-rc.2` is an upstream RC prerelease requiring Node.js `>=24.9.0`. The candidate is unpublished; final same-archive reports, Actions and publication are separate evidence. Historical or partial runs do not certify a revised final archive.

Use Linux with `/proc`, Node.js 24, pnpm 12.5.1 and Playwright Chromium:

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm check
```

| Group       | Development command     | Contract                                                                                                                                                                      |
| ----------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unit        | `pnpm test:unit`        | Authentication, TOTP/backup codes, sessions, Origin, language, storage/locks, exact support, consumer/archive/index and workflow rejection contracts                          |
| Integration | `pnpm test:integration` | Real HTTP/WebSocket, native readiness, cookies, mutations/revocation, real account PKCE and resource streaming/backpressure                                                   |
| CLI         | `pnpm test:cli`         | Real archive/profile execution, private terminal prompts, fixed English, invalid --lang before profile access, stable JSON, Unix sockets, offline locks and uncertain results |
| Browser     | `pnpm test:browser`     | Exact native DSH, anonymous/login/security/settings/workspace/chat/upload/preview, SSE/WebSocket, TLS/proxy and lifecycle boundaries                                          |

Development CLI/browser wrappers rebuild and repack; final loops must use the [fixed-archive consumer](../docs/development.md#consume-a-fixed-archive). `DSH_TEST_VERSION` accepts only the eight targets above. `DSH_TEST_BIN` must report that exact version; `DSH_TEST_BROWSER` may select an executable, otherwise use managed Chromium. Runtimes live in `.cache/test-runtime/<version>`; profiles are temporary. Ordinary development/smoke uses `.dev`; fixed-archive smoke owns a new marked short `.cache/v-*` root with independent runtime/home and `--port 0`. No command should use a real account directory.

Use pnpm copy-mode runtime installation and verify regular files have nlink=1 before HMR/fault edits. `isolatedDshEnv` allowlists Host variables without real credentials/endpoints; browser launch removes ambient proxy variables. Native model baseURL points at a local stub before first key entry, without preseeded keys or disabled onboarding. UI cases require zero model requests; proxy chat allows only expected local chat/title POSTs. Fixture close checks unexpected requests. The [TLS fixture guide](fixtures/tls/README.md) describes test-only certificates, SANs, trust and browser pinning; keys/profiles/task/screenshots/evidence are excluded from npm. Real IPv4/IPv6 HTTP/HTTPS and Node forwarding must work or fail, never silently skip.

`integration/account-login.test.ts` uses the locked real `@deepseek-ai/dsh-deepseek-account@0.2.2-rc.2` provider and local Platform endpoints for PKCE/redirect equality, state/URL/session ownership, one-time callback, cancellation/expiry/retry. Browser account cases exercise the actual provider installed per exact host. Observers choose the old platform package or merged account package explicitly, and read native effectiveConfig with config fallback only where that accessor is absent. Old hosts retain their actual SDK chain.

All eight hosts retain full manual-sign-in/settings coverage: instruction-first flow, failed loopback navigation then paste/confirm, blocked popups, initial/late preference reads, failed or unavailable mirrors, accepted settings and in-flight attempts. Eight-language visits, responsive light/dark UI, security overview/dialogs, keyboard/focus, TOTP/backup-code copying and sign-out/revocation persistence are checked; screenshots mask secrets. Native language catalogs are unchanged. The old locale cache stays ignored/retained, and published `0.2.0` technical-refusal fixtures retain their historical Chinese CLI contract.

Two mandatory `0.2.2-rc.2` account cases each prepare a private native runtime. They retain original entry/children/inject/options/disposer ownership, watch real client and native component source HMR, exercise true/false, unload/reinstall, third-party later writes, inactive-wrapper delegation, pending describe and active authorization cancellation. Local notification list/content/events cover language and lifecycle changes with no external/model requests or page errors. Cross-product notification localization mapping remains unverified. The private observation points and evidence limits are in `DSH-ACCOUNT-SLOT-001` in the [inventory](../docs/legacy-compatibility.md).

`live-config.spec.ts` observes actual Loader references/fibers, auth/store/lock/listener and SSE/WebSocket continuity through true→false→true→false and restart. `account-login.spec.ts` performs ordinary sessionHours configuration HMR, queued independent Settings writes and genuine nesting rejection. Native source-HMR fault tests retain the original instance on import failure, then throw after replacement initialization to check cleanup/rollback, lock nonces, mux closure and restored Settings save. Canonical file URLs/explicit watch roots and passive public logs do not replace native HMR services.

`startup-compatibility.spec.ts` damages only installed plugin copies on all eight: incompatible engines must cause Loader skip without import; an incompatible plugin admission range must refuse after import. Native webserver stays independently disabled, processes exit naturally nonzero, and TCP/HTTP/readiness/WebSocket probes all refuse. Host package identity, dependency graphs and candidate bytes are unchanged. The seven exact real host-release round trips, original session/settings and native version prompts are listed in [cross-version verification](../docs/development.md#cross-version-verification); minimum `0.2.1-rc.1` has no previous-host case.

Old Search/Fetch forms remain on `0.2.1-rc.2`, `0.2.1-rc.3`, `0.2.1-rc.4`, `0.2.1-rc.5`, `0.2.2-alpha.3`, `0.2.2-rc.1`. On `0.2.2-rc.2`, the native form independently selects auto/account/api-key billing for Search and Fetch. Tests cover refused saves/draft retention, refresh/restart persistence, credential save/replace/remove and no response echo, plus anonymous/revoked 401. Local model/Search/Fetch/outside call counters remain zero. Navigation on `0.2.1-rc.3`, `0.2.1-rc.4`, `0.2.1-rc.5`, `0.2.2-alpha.3`, `0.2.2-rc.1`, `0.2.2-rc.2` checks global/session/right-sidebar More, native settings/model selection and revocation. Public sessions/sessionProjections adds an empty completed turn without chat or snapshot replacement; Market/Creator visibility is checked without installation or external authorization. Dynamic official `/models` internals are unverified.

Exact `0.2.2-alpha.3`, `0.2.2-rc.1`, `0.2.2-rc.2` retain real native viewer/index/carrier isolation, asset/fallback/ETag GET/HEAD/304 and mux HTTPS/proxy/compression/expiry/revocation. Native Gateway/ws owns transport. Their shield tests cover native size/currentColor/selection, themes/narrow layouts, contribution release/default restoration and declaration withdrawal/recreation/disposal; the other five hosts retain default icons. Viewer clients install no administrator effects.

LiveShare is an officially published optional experimental plugin, disabled by default; this plugin does not enable it. Owner/Relay product E2E and exclusive stand-ins are removed. `business-origin-observer.mjs` uses actual Connection.fetch on the two exact Owner POST paths, without Host/Relay, priority WebServer bypass or fabricated Requests/waterfalls. Native-transport tests retain admission, validated outer Origin, single restoration pairs, raw duplicate/missing/bad/cross-site rejection, HTTP/HTTPS/proxy and real configuration-HMR behavior. Production adaptation/shared integration and capability checks remain. Product flows, production Relay/OAuth, visitor models and file writes are unverified; historical product reports apply only to their old archive.

Ordinary/full both run all eight complete CLI/browser/smoke targets. The [plan whitelist](../docs/development.md#ordinary-and-full-ci-plans) only selects extra retirement jobs. Full keeps independent technical refusal on `0.2.1-alpha.2`: real installation rollback and native whole-bundle peer skip with no delayed listeners, using published `0.2.0` as baseline. The six historical technical targets remain selectable only through `verify-retired.mjs`, outside DSH_TEST_VERSION. Ordinary skips that job.

Only validated plugin `0.3.6` full/releases additionally run `verify-maintenance-retired.mjs` on exact `0.2.1-alpha.3`, `0.2.1-alpha.4`, `0.2.1-alpha.5`. Three real CLI/HTTP cases per host verify warning-before-ready/once through real config/source HMR with continuous session then revocation, Loader skip, and post-import admission refusal/no listeners. `0.2.1-alpha.3` uses a Host peer fault; `0.2.1-alpha.4` and `0.2.1-alpha.5` use engines faults. Only private plugin copies change; native webserver remains disabled and no Chromium starts. This one-release suite lives outside the browser glob and does not restore support. Generic warning/date tests remain even though old positive Alpha-only branches are removed.

Every producer records source/archive identity. Consumer evidence sidecars preserve the old report schemas and link raw JSON/TAP/logs to actual CLI, lock, eight-package SDK chain and private-copy receipts. The index requires primary, independent smoke, exact previous-host and both private-account runtimes where applicable; omitted receipts/references, hashes, reports, mixed producers and partial suites fail. Full required-name checks also reject missing real account/notification/Search/Origin/viewer/resource/mux/HMR/icon cases; explicit per-version empty-file exceptions never count as real cases. CI checks strict success/expected skips and uploads original evidence plus a producer index outside npm. Final release verification is one archive with no build/pack inside consumption.

Linux/Node.js 24/Chromium, native loopback IPv4/IPv6 HTTP/HTTPS and existing Node forwarders define the test boundary. Other platforms/browsers/Node majors, real non-loopback IPv6 interfaces, Nginx/Traefik binaries, real external authorization, paid providers and cross-product notification localization are unverified. See [deployment](../docs/deployment.md) for backups, independent profiles and rollback with matching host/plugin/configuration/full data backup.
