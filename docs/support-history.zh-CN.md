## 如何阅读证据

- **D**：精确版本出现在所指 manifest 的 `dsh.compatibility.dshReleases`。各行单独标明已发布 npm 包、仅 Git tag 或未发布源码候选；声明本身不证明可获取性或实测通过。
- **R**：当时 README 将该精确 DSH 列为已测试或 CI 覆盖目标，tag 的 CI/runtime 也指向对应目标。这里只记录历史项目的报告，不声称取得了历史 Actions 成功记录，也不声称本次重跑了该旧归档。
- **R\***：后续 README 报告测试过较早的认证实现，没有证明当时使用了哪个旧 npm 归档。
- **V**：本轮开发对身份明确的候选归档进行了真实运行。同一 SHA-256 的十一版 Node.js 24 首轮 CLI、完整 browser 和安装 smoke 已通过；它只属于那个未发布候选，所有变更落定后的最终归档仍须重验。
- **未知**：在已核对的 npm manifest/README、Git tag、CI/runtime 和 changelog 中，没有找到该精确组合。仅满足 peer/runtime 范围表示技术准入，不能推导 D、R 或 V。表中未列组合也不等于已证明不兼容。

首轮 V 记录属于当时工作版本为 `0.1.10` 的旧候选，不是 `0.2.0` 的验证。其身份对应 SHA-256 `aac4843d079634e47b1d6e5a6f3c3bc4f7a29d41ec35c81993ab03bef6bb798e`，Node.js `24.21.0`，2026-10-19 的 CLI 99/99、完整 browser 599/599、smoke 11/11。原始报告保留在维护者的归档外验证记录中。本文及后续文档晚于该归档，这条记录不认证修订后的最终包。

历史插件行是存档证据，不是持续维护的逐插件版本测试矩阵。保留 `0.2.0` 的十一版、`0.3.1` 的七版以及已发布 `0.3.2` 的八版声明。已发布 `0.3.3` 独立声明九版，`0.3.4` 独立声明九版；六个退役宿主最后支持插件仍为 `0.2.0`。维护日期不自动改变技术准入或历史关系。

## 如何选择安装

已发布 `0.3.5` 保留十版历史声明，含三个 Alpha 与 `0.2.2-rc.1`，不含 `0.2.2-rc.2`。源码候选 `0.3.6` 新增 `0.2.2-rc.2`、维护退役 `0.2.1-alpha.3`、`0.2.1-alpha.4`、`0.2.1-alpha.5`，剩八版；候选声明和阶段专项不认证最终归档。`0.3.5` 是这三个 Alpha 的最后支持插件。已发布 `0.3.4`、`0.3.3`、`0.3.2` 分别保留九/九/八版历史。已核验 `0.2.0` 原归档 SHA-256 `7b4156a75398daef079435af85ff1387a26e94055e17871000e945299fc66efc`，仍是六个技术退役宿主的最后支持插件；`0.2.1-rc.3`、`0.2.1-rc.4`、`0.2.1-rc.5` 不继承其声明。

迁移目标为 DSH `0.2.2-rc.2` 与插件 `0.3.6`，候选未发布时仅使用已验证归档，成功发布后才从 npm 安装；宿主仍是上游 RC 预发布版本。已发布 `0.3.5` 仍可获取，并保留其十版历史声明。按[部署指南](deployment.zh-CN.md)先停服、备份完整 profile/认证状态/DSH 数据和配置，在独立 profile 演练后再操作，保持入口私有及 profile 级原生 webserver 独立禁用。回滚恢复原精确宿主、插件和对应数据备份，不承诺旧宿主读取任意新数据。Git-only `0.1.4`、未知组合和未声明未来宿主没有当前支持推荐；身份/API 检查继续生效。

DSH `0.2.2-alpha.2` 已在 `0.3.4` 按[2026-11-05 上游故障例外](support-policy.zh-CN.md#upstream-failure-exception)退役。新解析 SDK 会使原生设置回调失败，不安装本插件也能复现。已发布 `0.3.3` 仍可获取（2026-11-05 复核归档完整性），但历史声明不保证该全新依赖组合可用。2026-11-05 当时的迁移目标为 `0.2.2-alpha.3`；新迁移使用上方当前 RC 推荐。安装旧插件或早期通过报告均不能修复宿主。下方保留历史声明及原始 SDK 证据。

## 如何维护历史

两种语言、两个方向的表均人工维护。重新核实 registry 元数据及归档可获取性，检查精确 tag/包证据，区分 D/R/R\*/V 并记录核对日期。新增证据时同时更新两边单元格，保留稳定锚点。新发布插件须新增独立行和精确归档证据。实际 DSH 退役须按支持规范同步修改当前声明、运行适配、测试和历史，资格日期本身不改变这些表。不使用库存/历史生成器或专门 CI gate。
