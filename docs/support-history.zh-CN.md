# DSH 支持历史

[English](support-history.md)

`0.2.0` 发布前的 registry 基线，核对日期：**2026-10-19**。查阅完整 [DSH registry](https://registry.npmjs.org/@deepseek-ai/dsh) 和[插件 registry](https://registry.npmjs.org/dsh-auth-remote)，共 36 个 DSH 版本、10 个 npm 插件版本，另有仅确认 Git tag 的 `v0.1.4`。已下载全部 36 个 DSH 和 10 个插件归档并核验 registry integrity。可获取性只是该日期的观察，不等于兼容或维护承诺。

2026-10-28 的较早迁移准备记录：registry 列出 39 个 DSH 与 11 个插件版本，新增 DSH `0.2.1-rc.3`、`0.2.1-rc.4`、`0.2.2-alpha.2` 及插件 `0.2.0` 归档均下载并核验 integrity。当时 `0.2.2-alpha.2` 不在 `0.3.1` 的七版候选内。后续同日精确核验已发布 `0.3.1` 的 registry manifest 和归档，SHA-256 为 `519f64740e012e560925ceaf6305609cd81e8e5bb053fa8256d6ee01485dec22`；`0.3.2` 精确查询返回 404，现按未发布八版候选记录。上述可获取性均为带日期的观察。

从 [DSH → 插件](#by-dsh)或[插件 → DSH](#by-plugin)查询。当前候选承诺见 [README](../README.zh-CN.md#dsh-兼容性)和[兼容库存](legacy-compatibility.zh-CN.md)；两份支持规范保留前一发布记录。

## 如何阅读证据

- **D**：精确版本出现在所指 manifest 的 `dsh.compatibility.dshReleases`。各行单独标明已发布 npm 包、仅 Git tag 或未发布源码候选；声明本身不证明可获取性或实测通过。
- **R**：当时 README 将该精确 DSH 列为已测试或 CI 覆盖目标，tag 的 CI/runtime 也指向对应目标。这里只记录历史项目的报告，不声称取得了历史 Actions 成功记录，也不声称本次重跑了该旧归档。
- **R\***：后续 README 报告测试过较早的认证实现，没有证明当时使用了哪个旧 npm 归档。
- **V**：本轮开发对身份明确的候选归档进行了真实运行。同一 SHA-256 的十一版 Node.js 24 首轮 CLI、完整 browser 和安装 smoke 已通过；它只属于那个未发布候选，所有变更落定后的最终归档仍须重验。
- **未知**：在已核对的 npm manifest/README、Git tag、CI/runtime 和 changelog 中，没有找到该精确组合。仅满足 peer/runtime 范围表示技术准入，不能推导 D、R 或 V。表中未列组合也不等于已证明不兼容。

首轮 V 记录属于当时工作版本为 `0.1.10` 的旧候选，不是 `0.2.0` 的验证。其身份对应 SHA-256 `aac4843d079634e47b1d6e5a6f3c3bc4f7a29d41ec35c81993ab03bef6bb798e`，Node.js `24.21.0`，2026-10-19 的 CLI 99/99、完整 browser 599/599、smoke 11/11。原始报告保留在维护者的归档外验证记录中。本文及后续文档晚于该归档，这条记录不认证修订后的最终包。

历史插件行是存档证据，不是持续维护的逐插件版本测试矩阵。`0.2.0` 的十一版声明、已发布 `0.3.1` 的七版声明均保持历史事实。当前未发布 `0.3.2` 独立声明八版；六个退役宿主最后支持插件仍为 `0.2.0`。维护日期不自动改变技术准入或历史关系。

## 如何选择安装

已发布 `0.3.1` 可按其七版精确声明安装；它不包含 `0.2.2-alpha.2`。当前 `0.3.2` 尚未发布，须使用按本轮流程验证的本地归档，不能把旧归档成功转移给新包。`0.2.0` 在 2026-10-28 可下载，registry integrity 已核验，SHA-256 为 `7b4156a75398daef079435af85ff1387a26e94055e17871000e945299fc66efc`；它仍是六个退役宿主的最后支持插件。`0.2.1-rc.3`、`0.2.1-rc.4` 不继承 `0.2.0` 的声明。

迁移推荐 DSH `0.2.2-alpha.2` 与候选 `0.3.2`，按[部署指南](deployment.zh-CN.md)先停服备份、升级宿主，再安装新插件，保留 profile 级原生 webserver 独立禁用。回退须使用明确的旧宿主及 `0.2.0`，不改写已有 npm 版本。Git-only `0.1.4`、历史未知组合与未声明的未来宿主没有当前支持推荐；包身份/API 检查继续生效。
