# DSH 支持历史

[English](support-history.md)

`0.2.0` 发布前的 registry 基线，核对日期：**2026-10-19**。查阅完整 [DSH registry](https://registry.npmjs.org/@deepseek-ai/dsh) 和[插件 registry](https://registry.npmjs.org/dsh-auth-remote)，共 36 个 DSH 版本、10 个 npm 插件版本，另有仅确认 Git tag 的 `v0.1.4`。已下载全部 36 个 DSH 和 10 个插件归档并核验 registry integrity。可获取性只是该日期的观察，不等于兼容或维护承诺。

从 [DSH → 插件](#by-dsh)或[插件 → DSH](#by-plugin)开始查询。当前承诺以[支持规范](support-policy.zh-CN.md)和[兼容库存](legacy-compatibility.zh-CN.md)为准。

## 如何阅读证据

- **D**：精确版本出现在所指 manifest 的 `dsh.compatibility.dshReleases`。各行单独标明已发布 npm 包、仅 Git tag 或未发布源码候选；声明本身不证明可获取性或实测通过。
- **R**：当时 README 将该精确 DSH 列为已测试或 CI 覆盖目标，tag 的 CI/runtime 也指向对应目标。这里只记录历史项目的报告，不声称取得了历史 Actions 成功记录，也不声称本次重跑了该旧归档。
- **R\***：后续 README 报告测试过较早的认证实现，没有证明当时使用了哪个旧 npm 归档。
- **V**：本轮开发对身份明确的候选归档进行了真实运行。同一 SHA-256 的十一版 Node.js 24 首轮 CLI、完整 browser 和安装 smoke 已通过；它只属于那个未发布候选，所有变更落定后的最终归档仍须重验。
- **未知**：在已核对的 npm manifest/README、Git tag、CI/runtime 和 changelog 中，没有找到该精确组合。仅满足 peer/runtime 范围表示技术准入，不能推导 D、R 或 V。表中未列组合也不等于已证明不兼容。

首轮 V 记录属于当时工作版本为 `0.1.10` 的旧候选，不是 `0.2.0` 的验证。其身份对应 SHA-256 `aac4843d079634e47b1d6e5a6f3c3bc4f7a29d41ec35c81993ab03bef6bb798e`，Node.js `24.21.0`，2026-10-19 的 CLI 99/99、完整 browser 599/599、smoke 11/11。原始报告保留在维护者的归档外验证记录中。本文及后续文档晚于该归档，这条记录不认证修订后的最终包。

历史插件行是存档证据，并非持续维护的逐插件版本测试矩阵。DSH 维护层级单独判断：插件 `0.2.0` 仍声明十一版，其中六版 legacy，实际退役记录为空。日期到期不会自动移除支持；精确日期和退役要求见规范。

## 如何选择安装

对当前十一版 DSH，在[精确 registry 接口](https://registry.npmjs.org/dsh-auth-remote/0.2.0)确认可获取后选择插件 **`0.2.0`**。发布工作流须先验证最终归档，再执行发布。遵循[部署指南](deployment.zh-CN.md)，包括受保护远程部署时独立禁用原生监听。发布前 registry 基线最新为 `0.1.10`，仅声明截至 `0.2.1-alpha.5` 的九版；历史包能下载不等于仍适合新部署或刚刚重新验证通过。

DSH `0.2.1-rc.1`、`0.2.1-rc.2` 需要插件 `0.2.0`。发布准备期间，在发布成功前使用明确验证过的源码归档。`0.2.0` 不改变 npm `0.1.10` 的字节或承诺，也不能重新发布既有版本。本文不为 Git-only `0.1.4` 或历史未知的 DSH 版本推荐 npm 安装；不要关闭包身份/API 技术检查来强行运行旧组合。
