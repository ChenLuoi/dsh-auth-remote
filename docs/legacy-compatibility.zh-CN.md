- `dsh-runtime`：适用版本与支持集合仍有交集则保留相应适配；交集为空时，在同一次变更删除专属实现与测试，更新两种语言的矩阵、条目和指南。共享安全校验不随专属分支删除。

- 支持范围或共享宿主适配变更须对同一最终归档完整运行七版 CLI、browser、smoke，七版保留完整账号回归；普通固定选择见开发指南。full/发布独立验证退役边界 `0.2.1-alpha.2`，本次最终验收额外串行跑六版拒绝。

## 新能力迁移与退役流程

1. 新增或移除 DSH 版本时，同步修改两种语言的两个矩阵，保留完整版本号、条目 ID 和证据状态。
2. 新版能力变化时，从功能表找到涉及的每个版本，再打开相应条目核对安装包 API、代码及测试。能够使用相同 API 并有精确版本验证的版本可以迁移到共同实现；缺少能力或证据的版本继续保留对应分支，不能按发布时间推定可迁移。
3. 每个条目记录最终决策：保留哪些精确版本、迁移哪些精确版本、删除哪些专属实现和测试、仍缺什么证据。支持集合与适用集合有交集时，不整体删除该条目。
4. 公网 OAuth 可用性同时取决于 DeepSeek 平台和 DSH。官方允许公网 `redirect_uri` 后，还须验证 DSH 的来源策略、回调处理和 UI；满足 `DSH-ACCOUNT-001` 的条件后才撤除相应适配。
5. 人工同步复核两张表与条目。不引入兼容清单专用生成脚本或 CI 门禁；现有双语链接及打包检查继续使用。

## 共享安全边界

远程 profile 必须独立禁用原生 `webserver`。`tests/browser/startup-compatibility.spec.ts` 在七版验证 Loader skip/插件运行拒绝：最低 `0.2.1-alpha.3` 用 peer 故障，其余六版用 engines；`scripts/verify-retired.mjs` 在独立旧 profile 验证原样候选的安装回滚/完整包原生 peer skip，要求连续无 TCP/HTTP/readiness/WebSocket 监听并保留上游身份和审计。

`src/shared/dsh-support.ts` 在候选 `0.3.1` 明确记录三个 Alpha legacy、四个 RC 正常支持和六版退役（最后插件 `0.2.0`）。`retiredOn: 2026-10-28` 是准备日而非 npm 实际发布时间，不驱动停服；进程级/HMR 去重及必要 API、包身份、共享安全检查保留。当前日期见 README。

包身份、向前准入后的 API 检查、具体监听、原始 Host/Origin/Fetch Metadata、回环准入、密码/TOTP、会话、流撤销、存储故障与 CLI 确认适用于所有声明版本。反向代理 HTTPS → HTTP、Host 设置能力 `ownsHost` 和服务端原生浏览器认证交换也不能仅因某个适配退役而删除。

生产入口在官方 listener 初始化后校验绑定端口；失败须释放 listener、管理 socket 和存储锁。Connection 丢失或存储状态不可靠时撤回 ready 并关闭业务承载。不得伪造服务、关闭 Loader 启动审计或绕过原生 listener 来通过兼容检查。
