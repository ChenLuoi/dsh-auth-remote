## 范围与复核规则

插件 `0.2.0`（不扩写 npm `0.1.10` 历史）声明精确支持 DSH `0.1.7-rc.1`、`0.1.7-rc.2`、`0.2.0-rc.1`、`0.2.0-rc.2`、`0.2.1-alpha.1`、`0.2.1-alpha.2`、`0.2.1-alpha.3`、`0.2.1-alpha.4`、`0.2.1-alpha.5`、`0.2.1-rc.1`、`0.2.1-rc.2`，默认开发和测试版本为 `0.2.1-rc.2`。运行时范围 `>=0.1.7-rc.1` 包含预发布版本；向前准入不代表已验证，仍须检查包身份与必要 API。未列入矩阵的版本不继承验证结论；手动账号回填按 `>=0.2.1-alpha.3`（包含预发布）、必要 API 和动态 `manualAccountLogin` 配置准入，前向准入不代表已验证。

- 修改 peers、`dsh.compatibility`、运行时准入、测试目标、CI 或用户兼容声明前，对照两张矩阵及所有相关条目。
- `dsh-runtime`：适用版本与支持集合仍有交集则保留相应适配；交集为空时，在同一次变更删除专属实现与测试，更新两种语言的矩阵、条目和指南。共享安全校验不随专属分支删除。
- `plugin-contract`：按插件配置迁移政策退役，不能依据 DSH 版本退役。插件 `0.1.5` 的 `allowedOrigins` 输入仍由插件 `0.2.0` 兼容。
- 缺少精确版本证据时保留实现，明确登记缺口。不同版本通过相同测试，不证明其内部实现相同。
- 支持范围或共享宿主适配变更须执行同一最终产物的完整声明版本 CLI、浏览器和安装冒烟矩阵。`DSH-ACCOUNT-001` 专项完整回归针对 `0.2.1-alpha.3`、`0.2.1-alpha.4`、`0.2.1-alpha.5`、`0.2.1-rc.1`、`0.2.1-rc.2`；对 `0.1.7-rc.1`、`0.1.7-rc.2`、`0.2.0-rc.1`、`0.2.0-rc.2`、`0.2.1-alpha.1`、`0.2.1-alpha.2` 检查启动、设置入口和适配未启用即可。CLI/smoke 始终包含十一版；全量/发布 browser 同样全覆盖，普通低风险 browser 使用开发指南的固定计划。

## 新能力迁移与退役流程

1. 新增或移除 DSH 版本时，同步修改两种语言的两个矩阵，保留完整版本号、条目 ID 和证据状态。
2. 新版能力变化时，从功能表找到涉及的每个版本，再打开相应条目核对安装包 API、代码及测试。能够使用相同 API 并有精确版本验证的版本可以迁移到共同实现；缺少能力或证据的版本继续保留对应分支，不能按发布时间推定可迁移。
3. 每个条目记录最终决策：保留哪些精确版本、迁移哪些精确版本、删除哪些专属实现和测试、仍缺什么证据。支持集合与适用集合有交集时，不整体删除该条目。
4. 公网 OAuth 可用性同时取决于 DeepSeek 平台和 DSH。官方允许公网 `redirect_uri` 后，还须验证 DSH 的来源策略、回调处理和 UI；满足 `DSH-ACCOUNT-001` 的条件后才撤除相应适配。
5. 人工同步复核两张表与条目。不引入兼容清单专用生成脚本或 CI 门禁；现有双语链接及打包检查继续使用。

## 共享安全边界

受保护远程部署必须在 profile 补丁中独立禁用原生 `webserver`，被跳过的认证 bundle 无法应用自身禁用条目。`tests/browser/startup-compatibility.spec.ts` 在 `0.2.1-rc.1`、`0.2.1-rc.2` 使用损坏的隔离插件副本验证真实 bundle 跳过与插件侧运行拒绝，保留 Loader 审计及上游包。TCP、HTTP、readiness 与 WebSocket 升级探测均须拒绝连接；这些夹具仅建立拒绝路径证据。

插件 `0.2.0` 在 `src/shared/dsh-support.ts` 根据 manifest 精确声明和显式记录分类维护状态。六版仍在声明中并保持 legacy，没有真实退役记录或日历驱动的准入变化。启动诊断在同一进程中对每个精确版本/状态仅提示一次，配置及模块 HMR 也不重置；认证、必要 API 和包身份仍决定能否提供服务。单元/集成测试及 `tests/browser/account-login.spec.ts` 的真实 legacy/正常版 HMR 诊断覆盖此分离。日期与退役决策见[支持规范](support-policy.zh-CN.md)。

包身份、向前准入后的 API 检查、具体监听、原始 Host/Origin/Fetch Metadata、回环准入、密码/TOTP、会话、流撤销、存储故障与 CLI 确认适用于所有声明版本。反向代理 HTTPS → HTTP、Host 设置能力 `ownsHost` 和服务端原生浏览器认证交换也不能仅因某个适配退役而删除。

生产入口在官方 listener 初始化后校验绑定端口；失败须释放 listener、管理 socket 和存储锁。Connection 丢失或存储状态不可靠时撤回 ready 并关闭业务承载。不得伪造服务、关闭 Loader 启动审计或绕过原生 listener 来通过兼容检查。
