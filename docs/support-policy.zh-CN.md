# DSH 支持生命周期

[English](support-policy.md)

最后更新：2026-10-19。本规范区分维护承诺、精确版本验证和技术准入。插件 **`0.2.0`** 新增两个 `0.2.1` RC 的精确支持，新增 DSH 目标不扩写已发布插件 `0.1.10` 的历史支持。发布前必须验证最终 `0.2.0` 归档。

## 支持状态与运行准入

| 状态                                            | 维护与验证                                         | 运行行为                                             |
| ----------------------------------------------- | -------------------------------------------------- | ---------------------------------------------------- |
| 正常支持                                        | 维护已承诺功能，精确版本验证失败阻断发布           | 通过必要技术检查后运行                               |
| Legacy，含窗口过期但尚未实际退役                | 继续已承诺功能、兼容回归与安全修复，验证仍阻断发布 | 通过技术检查后运行，提示维护日期和迁移建议           |
| 在某次插件发布中明确实际退役                    | 撤销当前支持承诺和持续矩阵，保留历史证据           | 必要契约仍满足时可带提示尝试运行；准入不等于验证兼容 |
| 必要 API/行为缺失、必要适配已删除或安全检查失败 | 不宣称支持                                         | 拒绝提供受保护业务服务，给出升级或最后兼容插件路径   |
| 未评估的旧版或未来版                            | 无精确支持承诺                                     | 执行技术检查；启动成功不增加支持版本                 |

`dsh.compatibility.dshReleases` 记录精确支持声明；`engines.dsh`、DSH peer 和运行检查表达技术准入。插件 `0.2.0` 保持 `>=0.1.7-rc.1`（含预发布），同时检查包身份和必要 API。日历或纯维护退役不能机械提高下限。当前真实退役记录为空。

诊断应在启动日志中、提供受保护服务前输出：legacy 日期和迁移建议，或获准启动的未验证/已退役版本缺少当前支持承诺。同一进程每个精确版本/状态组合至多提示一次，HMR 也不重置。诊断不改变认证、登录弹窗、请求授权或 CLI JSON。

## 日期与 Alpha/RC 关联

一般 legacy 窗口为 **14 个自然日**。任何例外须由研发明确公告理由与期限，不按 alpha、RC 或正式版标签推算；不存在通用的 alpha 七天或正式版三十天政策。

日期使用 `Asia/Shanghai`。资格从 `legacySince + windowDays` 当地 00:00 起成立：2026-10-19 加 14 天为 2026-11-02，加 21 天为 2026-11-09。这是公告日期，不是自用户安装、上游发布或插件发布起算。窗口过期仅取得后续退役发布资格，不自动退役，也不强制在紧接着的插件发布退役。已安装插件行为不随日期改变。

同一基础版本的 alpha 跟随**整条 RC 发布线**：仍有任一正常支持 RC 时，关联 alpha 不自动进入 legacy。最后一个正常支持 RC 进入 legacy 时，未独立公告的关联 alpha 同时进入并共享截止日期。此规则适用于 `0.2.1-alpha.3`、`0.2.1-alpha.4`、`0.2.1-alpha.5`。`0.2.1-alpha.1`、`0.2.1-alpha.2` 使用独立能力边界例外，保留已公告的 21 天日期，后续 RC 不重新计时。

## 新增精确版本支持

1. 研发选择精确 DSH 版本。核对实际 registry 发布包、可获取性、完整性、对应 tag、API 以及安装后的 DSH → WebApp → 依赖链。Git tag、宽泛 SemVer、相邻版本或相同源码不足以证明可安装或兼容。
2. 阅读[兼容维护清单](legacy-compatibility.zh-CN.md)。同步候选依赖、声明、测试目标、两个库存矩阵和受影响条目；适用集合与支持集合仍有交集时保留适配，并保留共享安全检查。
3. 修正精确版本测试分支，确认预期用例真实注册。冻结一个候选 tgz，记录源码身份、归档 SHA-256、运行时组合、命令、测试数量和报告。所有当前支持版本（含 legacy）须使用同一归档通过 CLI、完整浏览器和隔离安装 smoke。影响归档的改动产生新候选，原最终矩阵随即失效。
4. 同步双语用户/开发文档及 Unreleased。只有发布已验证的新插件版本，才形成该已发布插件的正式历史支持记录；前向准入不增加支持版本。

## 公告进入 legacy

研发明确公告精确集合、原因、起算日、默认 14 天或有理由的例外、资格日、迁移目标、功能限制与运行准入政策。按影响同步声明、历史、README、库存及操作指南。Legacy 公告保持版本受支持，并保留发布阻断 CI。

整个 legacy 期间继续维护已承诺的认证和功能边界、兼容回归及安全修复；取得资格但尚未安排实际退役时也一样。记录继续 legacy，而不是删除验证任务。不得从上游发布日期选择日期或悄悄重置既有公告。

## 在未来发布中执行实际退役

插件 `0.2.0` **不执行实际退役**。未来退役变更须在同次变更满足以下所有项目：

1. 研发明确选定精确集合和生效新插件版本，时间不早于各资格日。记录生效日期、最后支持插件版本和已核实的分发可获取性。
2. 提供迁移和安装说明。区分维护退出与技术拒绝：删除视觉/测试专属适配本身不必阻止启动；缺少必要运行或安全契约必须拒绝服务。
3. 逐条比较 `dsh-runtime` 适用集合与结果支持集合；交集非空就保留，交集为空则同次删除独占实现和测试并同步中英文库存、两个方向矩阵及指南。缺证据须先取得精确版本证据，不能提前退役适配；保留共享认证、来源、会话、存储和传输检查。
4. `plugin-contract` 按其独立迁移政策处理。DSH 退役不移除 `allowedOrigins` 等旧插件配置。
5. 同步支持声明、CI、README、历史、库存及必要准入调整。记录实际退役、生效版本、最后兼容插件、升级路径和真实运行结果；保留历史行。
6. 对剩余全部支持版本验证最终归档，并验证拒绝路径不恢复未受保护的原生监听。保留[部署指南](deployment.zh-CN.md)中的独立 profile 保障与 readiness 检查。

已安装插件不得按日历定时退役；定时 CI 不得删除支持或验证。批准、日期、可获取性、适配证据、部署保障或最终验证缺少任何一项，都不能认定退役完成。

## 验证与交付规则

所有 PR 和主分支检查保留静态、单元、集成，以及全部支持版本的 CLI/安装 smoke。普通 browser 计划仅适用于明确低风险白名单；源码、共享行为、依赖、支持文档、构建/打包/消费机制、未知路径和不可靠差异均须全量。每周一 UTC 00:00（北京时间 08:00）、手动执行和发布固定全量精确版本矩阵。普通计划的代表验证不能替代其他版本的证据。

发布验证消费静态/核心检查后一次性生产的不可变归档。独立 job 核验相同归档身份和 SHA-256，恢复该包自己的 `dist`，并在隔离 profile 上串行运行文件。失败、取消、非预期跳过和零用例专项均须拒绝。发布依赖全部必要任务，消费已验证 artifact，不重新构建或打包。真实 GitHub Actions 结果与本地等价检查分别记录。

验证命令与隔离方式见[开发指南](development.zh-CN.md)，发布操作见[发布指南](releasing.zh-CN.md)。最终生产和同包验证使用 Node.js 24。测试凭据、任务文档、profile、截图和生成证据均不进入 npm 归档。

## 文档与证据职责

支持规范定义决策和操作；[支持历史](support-history.zh-CN.md)提供全部可核实发布版本的 [DSH → 插件](support-history.zh-CN.md#by-dsh)及[插件 → 精确 DSH](support-history.zh-CN.md#by-plugin)查询，包含可获取性、证据等级、日期和安装建议；[兼容维护清单](legacy-compatibility.zh-CN.md)维护功能 → 版本、版本 → 功能、稳定 ID、代码/测试与适配退役证据。README 只列当前正常/legacy 支持并链接明细查询；退出 README 不删除历史。

新增支持、legacy 公告和实际退役时同时维护这三个层次的中英文。区分历史明确声明、真实验证、仅技术准入与未知。只推荐已有证据且可获取的分发包；旧包仍可下载不等于仍在维护或已通过当前安全验证。缺失或不可获取时如实记录，不编造兼容。不能用新候选 manifest 重写历史发布支持。
